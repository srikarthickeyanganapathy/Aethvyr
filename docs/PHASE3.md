# Phase 3 security and privacy assessment

26 November 2026 · extension 2.10.0 · local release candidates

## Findings and changes

| Boundary | Finding | Implemented change |
| --- | --- | --- |
| Website access | The manifest requested all URL schemes, two DNR permissions on Chromium, and public access to implementation scripts. | Limited host and injection patterns to HTTP(S), removed activeTab, selected one DNR permission per target and exposed only the player HTML. Extension CSP explicitly requires packaged scripts and disables objects and base-URL overrides. |
| Header handling | Capture records grouped requests by a hostname and an inferred site and could survive a worker restart. | Only Authorization and X-Playback-Session-Id qualify for replay. Worker memory keys include the tab, frame, initiating origin and full destination URL, including scheme, port and query. Replay expires after 15 minutes. The previous session-storage capture key is removed. |
| Network rules | A static rule affected ordinary websites. Session rules could affect other requests on a shared host. | Removed the static rule from both distributions. Progressive playback uses an exact URL, extension initiator, tab and media type. Its Referer contains only the embedding origin. Rule cleanup is queued by tab. |
| Proxying | Direct fetch followed redirects and included ambient credentials. | Direct HTTP(S) reads omit cookies and fail on redirects. Passive probes and private reads use the owning frame. New automatically selected page-reported streams remain on the page route until browser observation or explicit selection. Cross-origin media dependencies use the page route with browser CORS enforcement. Disconnected Vault work is limited to its saved media origin. |
| Runtime messages | Several popup commands had no caller-specific gate. Session attachment relied too heavily on supplied IDs. | One-shot actions check the extension ID, caller class and applicable tab, frame and payload constraints. The player handshake checks URL parameters and the tab's registered session. An attached session binds to the player frame. Vault resume checks its top-level document and job ID. |
| Page messages and rendering | Page scripts can supply detection payloads and trigger work in the bridge. | The isolated relay selects bounded fields, caps reported URLs, checks the player origin on layout messages and validates proxy response shape, type, size and forwarded headers. Runtime media reads use bounded request IDs, GET/HEAD, filtered headers and an outstanding-request limit. Existing inert markup parsing, escaping and metadata projection remain in place. |
| Sync | Older snapshots can contain stream URLs, sensitive navigation and credential-like display text. | Opt-in sync v3 rewrites readable older snapshots through sanitizers. Stream fields are omitted, titles and labels redact common credential patterns, and private-host or recognizable direct-media page links are omitted. Site-profile fields and filter preset values are projected before sync. Deletion wins a history timestamp tie. An explicit empty bookmark set wins an equal nonzero timestamp conflict. |
| Data controls and diagnostics | History deletion alone does not clear bookmarks, and users needed a direct way to clear library organization. Prefetch warnings included the resource URL. | Added confirmed bulk bookmark and favorites/collections deletion in popup settings. Existing history, buffer, Vault and account deletion controls are documented in the privacy policy. Prefetch warnings record a status code. Exported diagnostics retain their field allowlist. |

## Verification

- All 53 Node tests passed, and ESLint passed. New fixtures cover malformed caller payloads, website versus popup authority, cross-tab/frame/origin capture separation, request-header filtering, URL and token redaction, and a sync v2 snapshot with a deletion conflict. The migration test verifies convergence after a second sync.
- Edge 158 passed the installed upgrade, launch, seek, close and native restoration checks. Vault paused and resumed two fixture exports, and both files matched the originals byte for byte. Private playback returned segment bytes inline. The fixture found no regular-profile private cache rows, download jobs, bookmarks or history entries.
- A separate Edge run played local HLS and DASH streams with a synthetic playlist credential. The fixture server required that credential on the playlists and rejected it on init and segment requests. It caught a passive metadata-probe race during development. The final build defers uncorroborated probes and skips passive reads of resources with an authentication capture. Reproduce with the Chromium runner’s `--security` option.
- Firefox 161 passed the legacy upgrade and repeat-install checks in separate disposable profiles with sync off and on. Both profiles passed their private-history checks.
- Both ZIPs validated against their unpacked builds. The production Shaka bundle and its license ship locally alongside the Anime4K notice. The initial npm audit reported five high and one moderate affected dependency entries. Compatible updates changed ten installed packages. The follow-up registry audit reported zero known vulnerabilities for the resulting tree.

## Remaining risks and release limits

- The direct transport authorizes the selected media **origin**. A shared origin can host multiple tenants. Header replay is narrower and requires the exact captured URL. Distinguishing every authorized segment within a multi-tenant origin would require reliable provenance for playlists, DASH templates, byte ranges and keys.
- Website scripts control MAIN-world messages and can observe or alter page-proxy results. Nonces correlate replies and cancellation. A reply from that world does not authenticate media or metadata. Very large transfers can still consume memory before the isolated bridge applies its response limit.
- Some credentialed CDNs require a full Referer, nonstandard headers, redirects or cross-origin cookies. Such streams can fail if the owning page cannot fetch them through its ordinary browser policy. The desktop fixtures cover progressive playback and exports. Live authenticated HLS/DASH services, third-party redirect chains and Android remain unqualified.
- Sync sanitization recognizes common sensitive formats. Free-form names, opaque paths and arbitrary user-entered strings can still reveal personal information. Offline devices retain their local copies. Deleting account data while another device is enabled can repopulate it. Older clients must update to write v3. Actual cross-device account delivery and recovery from quota interruption were not exercised in the installed-browser runs.
- The browser retains broad HTTP(S) host access for automatic detection. An optional per-site grant flow and optional downloads would change first-run and export interactions. Store-signed installation, enterprise policies, browser permission withholding and long-duration stress tests remain release work.
- An advisory scan describes known issues in the resolved dependency tree on the audit date. It does not establish the safety of all media inputs, browser implementations or bundled third-party code.
